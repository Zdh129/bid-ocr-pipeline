# 版面约束：预先声明的规则与变体（2026-11-19，伦敦时间，计分之前写定）

> 说明：写规则前，我看过基线 C 在这六套上的错误位置（`diag_C_spans.json`），知道主口径里与版面有关的错误主要集中在发票明细区的行序（synth18b 第16、17页，synth18e 第11页）。所以本测试**不是盲测**，规则可能偏向这些已知问题；结论需在新数据集上复核。规则写定后不再按分数调整；如有调整会在报告里单独标为「事后」。

## 输入（全部本地、已落盘）
- C 文本：方案E＋改进版⊗（与 `output/发票针对性优化/run.py` 的 C 逐字相同，输入版本同 `output/二次高精度OCR/common.py` 的 SETS）。
- A：百度高精度含位置版已保存的原始返回（`scheme_a/raw`，字级框，200 DPI px→pt），取自 SETS 第 4 列目录。
- 表格线：本地把扫描 PDF 渲染成 300 DPI，用 OpenCV 固定阈值 200 二值化，水平核（宽 = 页宽/25）和竖直核（高 = 页高/40）开运算取框线（`lines.py`）。
- 不调用任何外部服务；不改主路径代码、配置、冻结清单、参照。

## 通用约定
- 字符只搬家，不增删、不换字（每次改写断言字符多重集合不变）。
- C 的字逐个定位到 A 字框：先 SequenceMatcher 对齐，没对上的 ≥2 字连续片段再在未用 A 字里找最长公共片段；仍没对上的字跟随前一个已定位字。
- 定位覆盖率 < 85% 的区域不改。
- 改写后去空白文本与原来相同，记为「顺序不变，不改」。

## 规则一：发票明细区（在方案E已开的「发票重排 v3」结果之上叠加；条件替代）
- 触发：C 某个表格段同时含「项目名称」和其后的「价税合计」。区域 = 从「项目名称」起，到「价税合计」所在行之前。
- 区域上下界：表头上方最近的横线、「价税合计」上方最近的横线（检测不到就用 A 的锚点字框）；左右界取上界横线的端点。
- A 字框按行聚类成物理行（y 中心差 < 半字高）。
- **变体甲（行带重排）**：每条物理行一行，行内按 x 排。
- **变体乙（格子重排）**：表头行之后，「项目名称」列片段以「*」或「合」起头的物理行开新逻辑行，其余物理行并入上一逻辑行（折行）；列界优先用区域内竖线（≥3 条），否则用表头标签间的中点；逻辑行内按列从左到右、列内按（物理行, x）拼接。若没有任何「*」「合」起头的行，退回逐物理行。
- 与 v3 的关系：v3 用文档解析的单元格框+A字框重排，结果已在 C 里；规则一在 C 上再按 A 物理行和表头列界重建，只有覆盖率达标且顺序确实不同时才替换 v3 的结果。

## 规则二：通用有线表格·行带校验（变体丙才开）
- 触发：任意表格段（发票明细区除外），覆盖率达标，且其 x 范围内检测到 ≥3 条横线（有线表格/表单）。
- 横线把表格切成行带。C 的某一行里，若有 ≥2 个行带各含 ≥2 个定位字，判为「串行」。
- 有串行时，把第一条到最后一条串行行之间的 C 文字，按行带归组；行带内按该带内的竖线分列，列内按（物理行, x）拼接。

## 变体
- 甲：C ＋ 规则一（行带重排）
- 乙：C ＋ 规则一（格子重排）
- 丙：乙 ＋ 规则二

## 计分与统计
- 主口径 `tolerant_score.score_tolerant`（sign=in），严格口径 `blind20_score.score_system` 只作参考。
- blind20 用旧参照（`output/blind20_frozen/计分参照`），另报 `output/格式规则实装/参照_v2/` 校准参照。
- 每个被改写的区域单独加到 C 上，看所在页主口径错字数：减少＝修正，增加＝改错，不变＝不影响。
- 达标线：发票页（六集合计）读出率 ≥ 99% 且错字率 ≤ 1%。
